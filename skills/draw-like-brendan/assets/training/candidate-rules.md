# Candidate rules awaiting review

These are evidence-backed suggestions preserved for provenance. They are not active rules and must not affect rendering unless a user explicitly promotes them.

- Favor big, uneven, hand-built display lettering over polished diagram labels.
- When a dense systems explainer is explicitly requested, prefer an authored poster or annotated field sheet over a tidy product diagram.
- Make any boxes look like hand-drawn signs or containers, never clean UI cards.
- Use recurring motifs only when they carry meaning: stars, asterisks, accent marks, arrows, rough checks, batteries, tools, flags, dice, or eyes when seeing is the concept.
- Preserve source-specific awkwardness without adding arbitrary wobble.
- Reject a candidate that is merely legible but lacks authorship.
- Replace generic rounded boxes with signs, containers, paths, emblems, or open compositions.
- Reject SaaS card layouts, clean dashboards, and friendly whiteboard-explainer styling.
- Require a source-locked lettering pass and reject generic marker typography.
- Require one clear visual idea or thematic metaphor beyond flowchart correctness.
- Reduce visible text when explanation would become microcopy.

The original feedback referred to the bundled structure-only examples in `structure-references/`. Those images remain `style_authority: false`.
